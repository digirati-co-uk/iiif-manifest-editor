## Translation method and preservation

Prose additions use Google Translate drafts with protected placeholders, key
bindings and literal authored examples. French IIIF ranges use sequence context
rather than the unrelated musical meaning; Danish uses area context for the
standard structural term. Common actions and individual resource labels reuse the
existing explicit terminology tables. Short range/canvas and section/page count
labels have explicit locale-specific noun forms. Supported measurement unit
patterns come from Node 24's ICU/`Intl.NumberFormat` data; the remaining area and
nautical unit messages use the draft translation process.

Plural examples are selected using each locale's actual `Intl.PluralRules`,
including Czech fractional `many` versus integer `other`, Polish/Ukrainian
fractional `other`, and French/Spanish/Italian/Portuguese `many`. Numeric examples
are restored to the original named placeholders. When singular examples become
articles such as `eine` or `un`, the English singular message is translated again
with its placeholder protected directly. Whole messages remain independently
translated rather than assembled from translated fragments.

All **6,177 pre-existing values** in the affected files compare equal to the
pre-fill snapshot. Named values, `Range 1`, the `O` key binding and the generated
languages' existing tutorial/configuration literals are preserved. Catalog keys,
IIIF data and runtime/UI implementation are outside this fill. The generation
cache and temporary source snapshots are not a second repository translation
source; TypeScript catalogs remain authoritative.
