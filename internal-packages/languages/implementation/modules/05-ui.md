# UI package and duplicate widget audit

Status: Consumer implementation complete for the supported package surface; parent browser/release integration pending. Module: [`packages/ui`](../../../../packages/ui).

Determine which legacy/shared UI surfaces are shipped and migrate the supported ones, including dependency widgets.

## Prerequisites

- [Public i18n runtime and workspace bootstrap](01-public-runtime.md).

Namespace ownership for this implementation: **ui**. Common catalogs remain untouched to avoid overlap with module 04. [Source inventory](../inventories/05-ui.md)

## Files and surfaces to inspect

- `packages/ui/components`
- `packages/ui/madoc`
- `packages/ui/form-elements`
- `packages/ui/ui`

Paths identify starting points, not a complete allow-list. The inventory ranks actual files and gives individual locations. Proposed new paths are labelled as such; inspect existing exports and call sites before changing contracts.

## Implementation steps

1. Trace imports for the candidate files. Record which widget families remain active, which are examples and which should be removed separately; do not assume every candidate is shipped.

2. Localise active media/canvas widgets, loading/error states, callouts, form placeholders, help and ARIA strings using the shared runtime.

3. Check whether wrappers around date/time pickers, viewers, rich editors and React Aria need their own locale data/providers or translated props.

4. Keep generated media/annotation values, structural identifiers, URLs and author-entered text outside UI catalogs.

5. Track remaining dormant code explicitly instead of silently counting it as completed coverage.

## Acceptance checks

- [x] Each migrated supported widget family has a demonstrable caller or explicit supported direct API; dormant families are classified below.
- [ ] Browser layout review of media/canvas controls under pseudo/long text and RTL remains with the parent. Mounted DOM tests cover long wording and RTL dialog scope/state.
- [x] UI consumers use only the shared public runtime; no UI-local provider/context or private catalog import. Actual emitted consumer bundles remain a parent/release check because UI has no build of its own.

## Boundaries

This package contains duplication; migration is not permission to remove public APIs.

Keep stable IDs, protocol values and authored content outside UI lookups. Public code must not require the unpublished language package at runtime or in emitted declarations. Resolve references under the editor's shared public provider at render time; use fallback strings for definitions that have not yet migrated.

## Handoff

Record migrated directories, reviewed/exempted inventory entries, added semantic IDs, required namespaces and supported locale/profile combinations. Add translator context for placeholders and terminology. Link validation results and outstanding dependency UI to this guide. Mark this task complete only when its acceptance checks pass; seed catalogs alone do not complete a consumer migration.

### Third-party locale account

- `react-iiif-vault` playback/viewer state and Atlas provide mechanics. Editor-owned controls, loading labels and fallback media errors now translate here. Its VideoHTML renders a video plus a click handler without browser controls; there is no hidden stock play/pause menu to claim translated. Browser-supplied MediaError diagnostic strings remain verbatim, while missing-error fallback is Dutch/English. Media duration formatting remains positional minutes/seconds. Metadata callbacks keep their original dimensions/duration, and event listeners read the latest callback/translation without remounting media.
- `react-select-search@4.1.7` gets translated `placeholder` and `emptyMessage` props. Caller overrides, option names and selected values remain intact. The real installed dependency is exercised, not mocked. Its function component relies on `defaultProps`, which React 19 no longer applies; this wrapper supplies its class name and supported interaction defaults explicitly. No implicit locale provider or automatic option translation is claimed.
- `react-accessible-dropdown-menu-hook` and Floating UI supply focus/position/interaction mechanics, with display labels supplied by AppDropdown or its caller. Portal lang/dir updates use the same provider snapshot.
- `components/previewers/{UniversalViewer,UniversalViewerLazy,use-universalviewer}.tsx` and `components/organisms/PreviewView.tsx` are dormant internal source, not exported supported APIs and with no current outside caller. `universalviewer` is not installed/declared by this package; its CDN stylesheet/version and upstream chrome remain untouched. It does **not** become Dutch through the surrounding runtime. Reintroducing this family requires an explicit installed viewer/locale configuration and integration test.
- `madoc/components/Dropdown.tsx` wraps absent `react-functional-select` and has no supported export/current outside caller. Its upstream English defaults remain dormant, not counted as complete translations. `InlineSelect` renders caller-provided InternationalString values through its pre-existing missing legacy LocaleString alias; UI locale must not translate those values.
- No React Aria date picker or rich-editor implementation exists in this package. They live in `packages/editors` and belong to that module's owner. Existing package export entries for absent `RichTextLanguageField`, `NewManifestModal`, `PreviewButton`, and layout `Accordion/Accordion` predate this change; no API was removed or invented to conceal those missing targets.

### Runtime and preservation boundaries

Only the public `@manifest-editor/i18n` React entry and its public `core` types are used. No provider/context is defined here, and published source has no private-authoring import. `@manifest-editor/ui` is private and source-only, with no build/prepack/tsdown configuration to externalize; its runtime dependency is explicit. Publishing parent packages must keep that dependency external in their bundles/declarations. Emitted ESM/CJS context identity and tarball checks cannot be proven without prohibited builds and remain with parent/module 29.

Translations occur at display time. Tests preserve an authored Welsh annotation-page label, its resource URL, a copied URL, selected search values, numeric selector coordinates, edited dialog/form DOM nodes and callback arguments across locale/profile changes. No IIIF editing API, undo store or worker transport was changed. Whole-editor undo/worker/browser integration remains parent-owned. Exact-source Dutch cognate reviews were added only under `locales/en-GB/ui.ts` in `unchanged-nl.json`; no wildcard exemptions or fallback-only Dutch claims.
